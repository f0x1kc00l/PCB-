На плате мультивибратора хватало одного правила ширины на все дорожки. На настоящей плате цепи очень разные: силовые требуют широких дорожек, USB — пары с заданным импедансом, высоковольтные — больших зазоров. Писать правило для каждой цепи по отдельности долго и легко ошибиться. Цепи группируют в **классы (net classes)** и пишут правила для класса.

Аналогия: в школе правила пишут не для каждого ученика, а для класса — «7А обедает в 12:00». Новый ученик в 7А автоматически подчиняется этому правилу.

## Какие классы обычно заводят

| Класс | Цепи | Что для него настраивают |
|---|---|---|
| **Power** | +5V, +3V3, VBAT, VBUS | ширина дорожек, размер переходных отверстий |
| **GND** | GND, AGND | подключение к полигонам |
| **USB** | USB_D_P, USB_D_N | дифференциальная пара, импеданс, зазор до соседей |
| **HV** | цепи с высоким напряжением | увеличенный зазор |
| **Default** | всё остальное | общие правила |

## Создаём классы на плате

1. В редакторе платы выбери <MenuPath path="Design » Classes" />. Откроется **Object Class Explorer**.
2. Слева — дерево типов классов: цепи (Net), компоненты (Component), слои, площадки, дифференциальные пары и другие. Классы в угловых скобках, например `<All Nets>`, системные — их нельзя менять.
3. Правый клик по группе классов цепей → создать новый класс (в разделе компонентов команда называется **New Class**; для цепей проверь название пункта в своей версии [ПРОВЕРИТЬ]). Назови класс, например `Power`.
4. Выдели класс. В центре — список **Non-Members** (не входящие цепи), справа — **Members** (входящие). Перенеси нужные цепи кнопками между столбцами.

## Классы прямо из схемы

Лучше задавать классы в схеме: тогда они переносятся на плату при обновлении и не теряются при пересинхронизации.

- **Директива Parameter Set** с параметром **Net Class Name** прикрепляется к проводнику цепи. Значение параметра — имя класса. Ставится через <MenuPath path="Place » Directives » Parameter Set" verify />.
- Чтобы добавить в класс сразу много цепей, их накрывают **покрывалом (Blanket)** и ставят одну директиву Parameter Set, касающуюся края покрывала.
- Автоматические классы задаются в <MenuPath path="Project » Project Options" /> на вкладке **Class Generation**: например, **Generate Net Classes for Buses** создаёт класс на каждую именованную шину.

Классы попадают на плату при синхронизации схемы и платы (<MenuPath path="Design » Update PCB Document" />), через систему ECO. Какие классы переносятся, определяет вкладка **Comparator** в настройках проекта.

## Как правило «находит» объект

Каждое правило в редакторе правил (<MenuPath path="Design » Rules" />) имеет **область действия (Scope)** — запрос на языке Query, который отвечает на вопрос «к каким объектам применять». Новое правило по умолчанию имеет область `All` — ко всем объектам.

Примеры запросов:

| Запрос | Что выбирает |
|---|---|
| `All` | всё |
| `InNet('VBAT')` | объекты одной цепи |
| `InNetClass('Power')` | объекты всех цепей класса Power |
| `InNet('VBAT') And OnLayer('Bottom Layer')` | цепь VBAT, но только на нижнем слое |

Запрос можно набрать вручную, собрать в **Query Builder** (условия из списков) или в **Query Helper** (полный список ключевых слов и операторов).

### Приоритет

Если к объекту подходят несколько правил одного типа, Altium применяет **одно** — с наивысшим приоритетом.

<RulePriority />

- Чем **меньше число** приоритета, тем **выше** приоритет. 1 — самый главный.
- Приоритеты сравниваются только внутри одного типа правил (например, все правила Clearance между собой).
- Новое правило получает приоритет 1. Порядок меняют кнопкой **Priorities** в редакторе правил.
- Отсюда принцип: **частные правила — выше, общие — ниже**. Общее правило с областью `All` должно стоять последним, иначе оно «перекроет» все частные.

Исключение — правила **Matched Lengths**: они применяются все одновременно.
