В модуле 7 правила были простые: одна ширина, один зазор, один размер отверстия на всю плату. Теперь, когда есть классы (урок [9.3](../03-net-classes/)), можно описать плату гораздо точнее: силовые цепи — широкие, высоковольтные — с большими зазорами, сигнальные под микросхемой — тоньше.

Правила проектирования — это договор между тобой и заводом, записанный так, чтобы его проверял компьютер. Чем точнее договор, тем меньше сюрпризов.

## Категории правил

Редактор правил открывается командой <MenuPath path="Design » Rules" />. Слева дерево: категории → типы правил → сами правила. Категорий десять:

| Категория | Что в ней | Пример правила |
|---|---|---|
| **Electrical** | зазоры, короткие замыкания, неразведённые цепи | Clearance |
| **Routing** | ширина, переходные отверстия, слои, дифференциальные пары | Width, Routing Via Style, Differential Pairs Routing |
| **SMT** | расстояния для SMD-площадок | |
| **Mask** | расширение паяльной маски и пасты | Solder Mask Expansion |
| **Plane** | подключение к слоям-плоскостям и полигонам | Polygon Connect Style |
| **Testpoint** | контрольные точки | |
| **Manufacturing** | технологические ограничения | Hole Size, Minimum Annular Ring |
| **High Speed** | длины, согласование длин | Length, Matched Lengths |
| **Placement** | размещение компонентов | Component Clearance |
| **Signal Integrity** | параметры для анализа целостности сигналов | |

Новичку для двух- и четырёхслойной платы хватает правил из Electrical, Routing, Plane, Manufacturing и Mask. Остальные подключают по мере надобности.

## Правило с двумя областями: зазор между классами

Правило **Clearance** — особенное: оно описывает пару объектов, поэтому у него **две** области действия — для первого и для второго объекта.

Пример: класс `HV` (цепи 48 В) должен отстоять от всего остального на увеличенный зазор.

1. В <MenuPath path="Design » Rules" /> раскрой **Electrical › Clearance**, создай новое правило (правый клик → **Add Rule** [ПРОВЕРИТЬ точное название пункта]).
2. Назови его `Clearance_HV`.
3. Первая область: `InNetClass('HV')`. Вторая: `All`.
4. Задай минимальный зазор по таблице IPC-2221B для своего напряжения и условий (урок [5.5](../../m05-pcb-design/05-clearance/)), но не меньше технологической нормы производителя.
5. Нажми **Priorities** и убедись, что `Clearance_HV` выше общего `Clearance`.

<Callout type="warning">
  Числа зазоров в этом уроке не даются специально: они зависят от напряжения, наличия маски, условий эксплуатации и
  стандарта, по которому делается изделие. Бери их из таблицы 6-1 IPC-2221B (урок 5.5) и из норм производителя —
  выбирай большее из двух значений.
</Callout>

## Ширина и переходные отверстия по классам

**Width** (категория Routing) задаёт три значения: минимум, предпочтительное (**Preferred**) и максимум. При трассировке Altium берёт Preferred, клавиша <Kbd keys="3" /> перебирает Min, Preferred, Max и пользовательскую ширину.

Типовой набор:

| Правило | Область | Смысл |
|---|---|---|
| `Width_Power` | `InNetClass('Power')` | ширина по току из калькулятора |
| `Width_USB` | `InNetClass('USB')` | ширина из профиля импеданса (урок 9.5) |
| `Width` | `All` | ширина для обычных сигналов |

**Routing Via Style** задаёт диаметр переходного отверстия и площадки. Для класса Power имеет смысл отверстие крупнее: через маленькое переходное отверстие большой ток не пройдёт без нагрева. Клавиша <Kbd keys="4" /> при трассировке перебирает размеры отверстий из правила.

<Callout type="tip">
  Если в правиле ширины включить использование профиля импеданса из Layer Stack Manager, Altium сам подставит
  ширину для каждого слоя. Сменил стек — ширины пересчитались. Это надёжнее, чем вбивать числа вручную.
</Callout>

## Подключение к полигонам

**Polygon Connect Style** (категория Plane) определяет, как площадки и отверстия соединяются с полигоном:

- **Relief Connect** (с термобарьером) — площадка соединена с полигоном несколькими тонкими перемычками. Её легко паять: тепло паяльника не уходит в огромную медь.
- **Direct Connect** — площадка залита сплошь. Лучше для большого тока и отвода тепла, хуже для ручной пайки.

Типовое решение: для площадок выводных компонентов и SMD — термобарьеры, для переходных отверстий — прямое подключение. Это делается двумя правилами с разными областями (например, по типу объекта) и правильными приоритетами. Ключевые слова для выбора объектов по типу (например, `IsVia`, `IsPad`) найди в **Query Helper** — их набор и написание лучше проверить в своей версии.

## Правило для отдельной области

Под микросхемой с мелким шагом выводов дорожка общей ширины может не пройти между площадками. Решение — отдельное правило ширины с большим приоритетом, которое действует только в этой области: например, через **комнату (Room)** вокруг микросхемы или через запрос к компоненту. Запрос удобно собрать в **Query Builder**, выбрав условие из списка, а потом проверить, какие объекты он выбирает.

## Проверка: DRC

Правила проверяются двумя способами:

- **онлайн-проверка** — прямо при трассировке Altium подсвечивает нарушения;
- **пакетная проверка** — запуск всех проверок и отчёт, урок [7.7](../../m07-multivibrator/07-drc/).

Если DRC показывает сотни нарушений сразу после добавления правила, сначала подумай, не ошибка ли в самом правиле: неправильная область, перепутанный приоритет, слишком жёсткое значение.
