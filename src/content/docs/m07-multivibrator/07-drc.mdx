Плата разведена — но правильно ли? **DRC (Design Rule Check)** проверяет всю плату на соответствие правилам: зазоры, ширины, отверстия, маску, неразведённые связи. Ни одну плату нельзя отправлять на производство без чистого DRC.

<TutorialFlow current={7} />

## Шаг 1. Запуск проверки

1. <MenuPath path="Tools » Design Rule Check" />. Откроется диалог **Design Rule Checker**. В нём же настраивается и онлайн-проверка (во время рисования), и пакетная (по кнопке).
2. Страница **Report Options**: включи **Create Report File**.
3. Страница **Rules to Check**: правый клик в таблице → **Batch DRC - Used On**. Будут проверяться только правила, которые реально используются.
4. Раскрой раздел **Testpoint** и сними галочки **Batch** у его четырёх правил: тестовых точек на учебной плате нет.
5. Нажми кнопку запуска проверки внизу диалога.

<Screenshot src="screenshots/m07-multivibrator/l07-drc-dialog.png" alt="диалог Design Rule Checker: страница Rules to Check, раздел Testpoint без галочек Batch" />

## Шаг 2. Читаем результат

После проверки откроется вкладка **Design Rule Verification Report**, а нарушения появятся в панели **Messages**.

- Вверху отчёта — список проверенных правил и число нарушений по каждому. Щелчок по правилу ведёт к его нарушениям.
- Ниже — каждое нарушение с объектами. Щелчок переводит к объекту на плате.
- В **Messages** то же самое: двойной щелчок по строке — переход к месту.
- На плате нарушающие объекты отмечены маркером (по умолчанию зелёные кружки с крестом). В подробностях указано фактическое значение и предел, например «0.017mm < 0.254mm».

По руководству ожидаются нарушения двух видов, не меньше чем по четыре штуки: **Minimum Solder Mask Sliver** и **Clearance Constraint**. Оба — из-за транзисторов в корпусе TO-92.

## Нарушение 1. Зазор между выводами транзистора

Выводы TO-92 стоят плотно: зазор по меди между соседними площадками около **0,22 мм**, а правило требует 0,25 мм.

Варианты исправления:

1. уменьшить площадки транзистора — портит посадочное место и пайку;
2. ослабить правило для всех — снижает требования ко всей плате;
3. ослабить правило **точечно** — только для того, что реально мешает.

Руководство выбирает ослабить зазор именно для пары «площадка выводного компонента — площадка выводного компонента», потому что 0,22 мм всё ещё легко делается на производстве:

1. Перейди на вкладку платы, <MenuPath path="Design » Constraint Manager" />.
2. Вид **Clearances**, щёлкни ячейку **All Nets / All Nets**.
3. В таблице внизу задай **TH Pad – to – TH Pad** = `0.22` и нажми Enter.
4. <MenuPath path="File » Save to PCB" />.

**Почему так.** Правило с разными зазорами для разных типов объектов — нормальная практика: между выводами компонента производитель обычно справляется с меньшим зазором, чем мы заложили для дорожек. Если бы рядом были другие тесные выводные площадки, лучше было бы сделать отдельное правило только для транзисторов — так советует и руководство. Решение «0,22 мм — это нормально» опирается на нормы производителя (урок [5.5](../../m05-pcb-design/05-clearance/)), а не на желание избавиться от красного маркера.

## Нарушение 2. Узкая полоска маски

Окна в паяльной маске по умолчанию больше площадок на 0,1016 мм (4 mil) с каждой стороны — запас на неточность совмещения маски. Между соседними выводами TO-92 от маски остаётся полоска около **0,017 мм** (рис. 7.4), а правило **Minimum Solder Mask Sliver** требует 0,254 мм. Такую полоску завод не напечатает: она либо отвалится, либо её уберут, и это нужно учесть в правилах.

Руководство делает два изменения сразу.

**Уменьшить минимальную полоску:**

1. В Constraint Manager вид **All Rules**.
2. В дереве **Manufacturing** → **Solder Mask Sliver** → правило **MinimumSolderMaskSliver**.
3. **Minimum Solder Mask Sliver** = `0.22`.

**Убрать расширение маски только у транзисторов:**

1. В дереве **Mask** → **Solder Mask Expansion**. Существующее правило **SolderMaskExpansion** (0,1016 мм) не трогаем.
2. Правый клик в свободной области таблицы → **Add Custom Rule**. Появится **SolderMaskExpansion_1**, переименуй его двойным щелчком в `SolderMaskExpansion_Transistor`.
3. Рядом с **Object Match** нажми кнопку области действия → **Open Query Builder**.
4. В **Building Query from Board** выбери **Condition Type / Operator** = **Associated with Footprint**, **Condition Value** = **ONSC-TO-92-3-29-11** → **OK**. Запрос станет `HasFootprint('ONSC-TO-92-3-29-11')`.
5. **Expansion top** и **Expansion bottom** = `0`.
6. <MenuPath path="File » Save to PCB" />, закрой вкладку ограничений (правый клик → **Close Multivibrator.PcbDoc [Constraints]**) и сохрани плату.

<Screenshot src="screenshots/m07-multivibrator/l07-query-builder.png" alt="Query Builder: Associated with Footprint = ONSC-TO-92-3-29-11 для правила SolderMaskExpansion_Transistor" />

**Почему так.** Без расширения окна маски совпадают с площадками, и между выводами транзистора остаётся полоска шириной во весь медный зазор — 0,22 мм, что уже проходит по новому правилу. Расширение убрано **только** у транзисторов: остальным площадкам запас маски нужен. Менять расширение для всей платы руководство отказывается — для недорогой двухслойной платы это рискованно.

<Callout type="altium">
  Имя посадочного места `ONSC-TO-92-3-29-11` пришло вместе с компонентом из урока 7.2. Если ты взял транзистор другого
  производителя, имя будет другим — выбери своё в выпадающем списке **Condition Value**. Правило с запросом (query) —
  мощный инструмент: можно применять правила к классам цепей, компонентам, слоям. К нему вернёмся в уроке
  [9.4](../../m09-advanced/04-advanced-rules/).
</Callout>

## Шаг 3. Повторная проверка и подготовка к выпуску

1. Снова <MenuPath path="Tools » Design Rule Check" />, **Create Report File** включён, запуск.
2. Отчёт должен быть **без нарушений**. Если что-то осталось — исправь и проверь снова.
3. Удали отчёт из проекта: в **Projects**, раздел **Generated\Documents**, правый клик по отчёту → **Remove from Project** → удалить файл.
4. Правый клик по любой вкладке → **Close All Documents**.
5. **Save to Server** рядом с проектом, комментарий, например `PCB design complete`, → **OK**.

<Callout type="warning">
  Чистый DRC проверяет только то, что ты описал правилами. Он не знает, что разъём перевёрнут или транзистор не той
  проводимости. Поэтому после DRC — визуальная проверка по чек-листу (приложение C) и сверка со схемой.
</Callout>
