## Зачем Output Job

В уроках 10.2–10.5 мы генерировали каждый файл отдельной командой. Это работает один раз. Но плату переделывают: поправил дорожку — выгружай всё заново и не забудь ни одной галочки. Рано или поздно на завод уйдут Gerber от новой версии и сверловка от старой.

**Output Job** (файл `.OutJob`) решает эту проблему: это **сохранённый рецепт выпуска**. В нём перечислены все выходы с их настройками и указано, куда класть результат. Выпуск всего комплекта — пара щелчков, и каждый раз одинаково.

Аналогия: технологическая карта на кухне ресторана. Повар не вспоминает рецепт заново, а идёт по карте — поэтому блюдо всегда одинаковое.

## Создание Output Job

<MenuPath path="File » New » Output Job File" /> или правый клик по проекту в панели **Projects** → <MenuPath path="Add New to Project » Output Job File" />. Файл появляется в папке проекта **Settings\Output Job Files**. Сохрани его под понятным именем.

<Callout type="tip">
  Сделай **два** OutJob: `Fabrication.OutJob` (изготовление) и `Assembly.OutJob` (сборка). Project Releaser при первом
  открытии сам привязывает OutJob с именами, начинающимися на «fab» и «ass», к данным изготовления и сборки.
</Callout>

## Устройство редактора OutJob

- **Outputs** — список выходов по категориям: **Fabrication Outputs**, **Assembly Outputs**, **Report Outputs**, **Validation Outputs**, **Documentation Outputs** и другие. Внизу каждой категории — ссылка **Add New … Output**.
- **Output Containers** — куда складывать результат. По умолчанию есть **PDF**, **Folder Structure** и **Video**; новые добавляются через **[Add New Output Container]**.
- Колонка **Enabled** — связывает выход с выбранным контейнером. Включённые выходы нумеруются: это порядок генерации.
- **Variant Choice** — для какого варианта сборки генерировать (если используешь варианты).

## Наполняем Fabrication.OutJob

1. **Fabrication Outputs** → **Add New Fabrication Output** → **Gerber Files** → выбрать плату. Двойной щелчок по выходу открывает тот же Gerber Setup, что в уроке 10.2: настрой слои и единицы.
2. Так же добавь **NC Drill Files** (урок 10.3). При желании добавь **ODB++** или **IPC-2581**.
3. **Validation Outputs** → **Design Rules Check** → плата. Отчёт DRC ляжет рядом с файлами, а Project Releaser остановит выпуск, если проверка не пройдена.
4. Выбери контейнер **Folder Structure** и включи для всех этих выходов радиокнопки в колонке **Enabled**.

## Наполняем Assembly.OutJob

1. **Report Outputs** → **Bill of Materials** → ActiveBOM (урок 10.4). Формат и шаблон — в настройках выхода.
2. **Assembly Outputs** → **Generates pick and place files** → плата (урок 10.5).
3. **Documentation Outputs** → **Draftsman** → чертежи из урока 10.7.
4. Свяжи BOM и чертежи с контейнером **PDF**, а Pick&Place — с **Folder Structure**.

## Контейнеры и генерация

Щелчок по ссылке **Change** у контейнера открывает его настройки. Главное — базовый путь:

- **Release Managed** — путь задаёт процесс выпуска (Project Releaser). Это вариант по умолчанию для работы с рабочим пространством.
- **Manually Managed** — путь задаёшь сам, можно относительный (**Use relative path**). Это вариант, если ты работаешь без Altium 365 и хочешь получить файлы в папке проекта.

Для PDF-контейнера можно выбрать, собирать ли всё в один файл или делать отдельный PDF на каждый выход.

Генерация: ссылка **Generate content** у контейнера или клавиша <Kbd keys="F9" />. Для папки — также <MenuPath path="Tools » Run" />, для PDF — <MenuPath path="Tools » Generate" />. Каждый контейнер генерируется отдельно: пакетной генерации всех контейнеров сразу в OutJob нет.

## Project Releaser

**Выпуск (release)** — это не просто «сгенерировал файлы». Это зафиксированный снимок проекта: исходники, все выходные файлы и номер ревизии, которые потом нельзя случайно поменять. По выпуску всегда можно ответить на вопрос «что именно мы отправили на завод в марте».

Запуск: <MenuPath path="Project » Project Releaser" /> или правый клик по проекту → **Project Releaser**. Этапы:

1. **Configure Server Release** — настройка выпуска (кнопка **Options** → вкладка **Release Options**, где назначаются Output Jobs для данных изготовления и сборки);
2. **Validate Project** — проверки, например DRC; при ошибке выпуск останавливается;
3. **Generate Data** — генерация всех выходов из назначенных OutJob;
4. **Review Data** — просмотр того, что получилось;
5. **Upload Data** — загрузка в рабочее пространство с примечанием к выпуску (Release Note);
6. **Execution Report** — отчёт.

<Callout type="altium">
  Project Releaser в учебнике Altium показан для выпуска в подключённое рабочее пространство Altium 365 (Workspace).
  Если ты работаешь без него, используй контейнеры с **Manually Managed** путём и генерируй файлы вручную, а ревизии
  веди сам: папка `release/rev-A/` с архивом файлов и коротким текстом «что изменилось». Возможность локального выпуска
  без рабочего пространства в Altium Designer 26 [ПРОВЕРИТЬ].
</Callout>

## Практика

1. Создай в проекте мультивибратора `Fabrication.OutJob` и `Assembly.OutJob` по шагам выше.
2. Для Folder Structure выбери **Manually Managed** и относительный путь `Outputs`.
3. Сгенерируй оба комплекта. Сравни с файлами, которые ты выгружал вручную в уроках 10.2–10.5. Должно получиться то же самое.
4. Поменяй на плате любую дорожку, снова сгенерируй и убедись, что обновились все файлы.
